## 一、 数据集与比对基础

## 二、 GalTranslPP 架构机制对审查结论的影响

结合 `GalTranslPP` 源码实现，GPT 字典（`ProjGptDict.toml`）的工作链路如下：
1. **动态 Prompt 注入**：`batchText.contains(entry.org)` 时，动态生成 Markdown 表格 `| Src | Dst(||Dst2||..) | Note |` 发送给 LLM；
2. **多译名支持**：原生支持 `||` 分隔候选译名（`checkTransIncludeReplace`）；
3. **自动化质检（QA Check）**：翻译完成后，`ProblemAnalyzer` 检查译文是否包含 `rep` 中的词，若不包含则抛出 **`DictionaryUnused`（字典未使用）** 警告；
4. **超集词识别机制（`supersetEntryIndices`）**：按词长降序排序，当长词被使用时，可豁免短词的未用报警。

> **核心结论变化结论**：
> - **人设与常识误译项更加致命**：因为 note 会直接作为提示词指导大模型，错误的 note 会强行诱导大模型产生严重幻觉误译；
> - **`||` 语法是官方推荐规范**：本体字典和建议修改中的 `||` 语法完美适配 GalTranslPP 的表头与质检算法；
> - **“切词破坏”升华为“质检误报与超集词保护”**：补充长复合词（如 `夢の主役`）不仅是给 LLM 提示，更是为了防止 GalTranslPP 误报 `DictionaryUnused`；
> - **严禁在 `rep` 中携带句末标点**：GalTranslPP 用严格子串 `contains` 做质检，带叹号会导致标点不匹配而报字典未使用。

## 三、 关键缺陷与重大问题详析

### 1. 与本体字典直接冲突、严重混淆人设：`兄さん方`

* **FD 字典现状**：
  ```toml
  {org = "兄さん方", rep = "哥哥们", note = "旁白中对莲乃家男性们的合称。"}
  ```
* **本体字典定稿**：
  ```toml
  {org = "兄さん方", rep = "几位大哥||大哥们", note = "对莲乃警备男员工们的称呼（几位大哥／大哥们）。"}
  ```
* **本体实际翻译（`transl_cache`）**：
  * 「……我和部长进行假约会的时候，正好和莲乃警备的**几位大哥**撞了个正着。」
  * 「接着**大哥们**开玩笑地叫我什么『少爷』啦『少主』啦……」
* **FD 原文语境（`s05b01b.ps3.json`）**：
  > `咲や兄さん方が持って来てくれたゲームをしたり`（玩着咲和大哥们带过来的游戏）
* **在 GalTranslPP 下的影响**：
  在本作中咲为独生女，指代莲乃警备保障的男员工们。如果维持 `rep = "哥哥们"`：
  1. LLM 会收到 `| 兄さん方 | 哥哥们 | 旁白中对莲乃家男性们的合称。 |`，被严重误导而破坏人设；
  2. 若 LLM 结合上下文自主翻为“大哥们”，GalTranslPP 质检引擎因在译文中找不到“哥哥们”，会触发 **`DictionaryUnused` 报错**！
* **修改对齐建议**：
  ```toml
  {org = "兄さん方", rep = "几位大哥||大哥们", note = "对莲乃警备男员工们的称呼（几位大哥／大哥们）。"},
  ```

---

### 2. 严重常识误译（望文生义）：`ミルクポーション`

* **FD 字典现状**：
  ```toml
  {org = "ミルクポーション", rep = "牛奶药水", note = "咖啡用的牛奶；被叫成药水（potion）的玩笑说法。"}
  ```
* **FD 原文语境（`s01p07.ps3.json`）**：
  > 弥生：`「了解ー。その辺にポーションあるから好きに使っていいわよ」`  
  > 旁白：`すっかり入り浸るうちに、部長が使いもしないのに揃っているガムシロップや、ミルクポーションを指差す。`
* **在 GalTranslPP 下的影响**：
  `ミルクポーション` 是日本咖啡行业标准词（portion milk，分装奶球/咖啡伴侣小胶囊），搭配果糖球 `ガムシロップ`。
  由于 GalTranslPP 将 `note` 全文作为提示词表格输出给模型，模型看到带有“药水玩笑”的解释后，会**强行执行幻觉逻辑**，把日常喝咖啡写成喝奇幻魔法药水。
* **修改建议**：
  ```toml
  {org = "ミルクポーション", rep = "咖啡奶球||奶精球", note = "咖啡用的淡奶精球（portion milk），非奇幻药水。"},
  {org = "ポーション", rep = "奶精球||咖啡奶球", note = "弥生在准备室指咖啡淡奶球（portion），口语省略说法。"},
  ```

---

### 3. 人称与语境指代严重误判：`内藤さん`

* **FD 字典现状**：
  ```toml
  {org = "内藤さん", rep = "内藤", note = "景子对透的敬称（省略さん）。"}
  ```
* **FD 原文语境（`s05e99.ps3.json`）**：
  > 景子：`『センパイと付き合うと、もれなく内藤さんがついて来ますから。こう、覚悟が必要ですよね』`
* **在 GalTranslPP 下的影响**：
  景子管透叫“前辈”，句中“内藤さん”明确指**透的妹妹内藤舞亚**。字典不仅误导模型把指代对象当作透，还强行剥离敬称，导致大模型生成“附带内藤”这样丧失语境情调的生硬译文。
* **修改建议**：
  ```toml
  {org = "内藤さん", rep = "内藤小姐||内藤小妹", note = "景子调侃透时指其妹妹内藤舞亚，非称呼透本人。"},
  ```

---

### 4. 本体字典收录且在 FD 原文中出现，但 FD 字典遗漏的条目

GalTranslPP 只有在当前 batch 文本命中 `org` 时才会向模型注入条目。以下两条遗漏会导致模型失去关键指引：

1. **`ありす`**（FD 出现 3 处）：
   * 出处：`s03x04`（有子求证：““ありす”だったよね……”）及 H 场景低语。遗漏会导致模型保留假名或译成爱丽丝。
   * 补入建议：
     ```toml
     {org = "ありす", rep = "有栖", note = "有栖的平假名表记（有子台词提及及H场景低语）。"},
     ```
2. **`まいあ`**（FD 出现 1 处）：
   * 出处：`s05a01c`（H 场景娇喘低语）。
   * 补入建议：
     ```toml
     {org = "まいあ", rep = "舞亚", note = "舞亜的平假名表记（H场景低语）。"},
     ```

## 四、 翻译风格与 GalTranslPP 质检机制对齐

### 1. 标点符号与 QA 子串质检：`のーさんきゅー`
* **现状**：`rep = "不用啦，谢谢！"`（rep 自带感叹号）。
* **在 GalTranslPP 下的影响**：
  GalTranslPP 质检代码：`trans.contains(subStr)` 为严格子串匹配。如果模型句尾翻成逗号或句号，会因为感叹号不匹配直接被判定为 **`DictionaryUnused` 警告**。
* **修改建议**：
  ```toml
  {org = "のーさんきゅー", rep = "不用了，谢谢||敬谢不敏||不用啦，谢谢", note = "「No, thank you」口语谐音，去掉尾部标点。"},
  ```

### 2. 超集词质检保护：`夢の主` vs `夢の主役` / `夢の主導権`
* **现状**：FD 字典只有 `{org = "夢の主", rep = "梦主"}`。
* **在 GalTranslPP 下的影响**：
  当原文出现 `夢の主役`（梦境主角）时，模型翻出“梦境的主角”，译文不含“梦主”。由于字典没有收录超集词 `夢の主役`，`entry.supersetEntryIndices` 为空，**GalTranslPP 会误报：`GPT字典 '夢の主'->'梦主' 未使用`**。收录超集词能正确建立父级引用，避免误报。
* **修改建议**：
  ```toml
  {org = "夢の主役", rep = "梦境的主角||梦的主角", note = "超集词保护，防止「夢の主」误报未用。"},
  {org = "夢の主導権", rep = "梦境的主导权", note = "超集词保护，防止「夢の主」误报未用。"},
  {org = "夢の主", rep = "梦境的主人||梦主", note = "梦境的主人／支配者。"},
  ```

### 3. 爱丽丝典故术语精度：`帽子屋` 与 `いかれ帽子屋`
* **现状**：两者均设为 `疯帽子`。
* **对齐本体**：本体仅在 `イカレ帽子屋`（Mad Hatter）出现时译为 `疯帽子`。普通 `帽子屋`（Hatter）宜设为 `帽匠||帽子屋`。

---

## 五、 冗余条目清理建议

1. **清理带问号条目（`咲？`、`舞亜？`）**：
   在 GalTranslPP 中，原文出现 `咲？` 会同时触发 `咲` 和 `咲？` 两个条目，向 LLM 注入重复表格行，浪费 Prompt 上下文，建议清理。
2. **清理不对称章节标题（`第１ブロック・咲編`）**：
   已有泛用条目 `第１ブロック`，保留单个性条目无必要，建议清理。
