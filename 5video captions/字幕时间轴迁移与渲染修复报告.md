# 字幕时间轴迁移与渲染修复报告

> 2026-11-04  
> 关联文档：[`..\视频解包与字幕时间轴报告.md`](../视频解包与字幕时间轴报告.md)  
> 范围：本体、FD、RE 三套 OP 特效字幕脚本的时间轴迁移、渲染管线修复与成片验证。

---

## 0. 结论

三套字幕脚本已经从旧版视频时间轴迁移到当前修正版视频时间轴，并完成渲染管线修复。

最终三支成片全部通过帧数校验：

| 游戏 | 成片 | 帧数 | 时长 | 视频 | 音频 |
|---|---|---:|---:|---|---|
| 本体 | `本体/本体op_字幕成片.mkv` | 3173 / 3173 | 135.628s | H.264 | Vorbis 原轨复制 |
| FD | `FD/FDop_字幕成片.mkv` | 3089 / 3089 | 132.006s | H.264 | Vorbis 原轨复制 |
| RE | `RE/REop_字幕成片.mkv` | 2427 / 2427 | 103.012s | H.264 | Vorbis 原轨复制 |

关键结论：

1. 当前 `本体/op.mkv`、`FD/op.mkv`、`RE/opre.mkv` 是正确时间轴版本；`旧版/` 目录中的文件才是 FFmpeg 直接重封装产生的错误时间轴版本，不能拿来覆盖当前文件。
2. 字幕歌词时间不需要整体平移。歌词跟音频绝对时间走，只有绑定了“原片画面切镜”的视觉特效锚点需要迁移。
3. 渲染流程不能用 FFmpeg 默认帧同步或 `vfr`，否则会丢末尾长静止段后的主帧。最终使用 `passthrough`，并让字幕裸流比基底末尾多生成 1 帧。
4. FD 还有一处额外边界：`config.DUR` 会把字幕裸流截断到基底最后一帧之前。三套 `gen.py` 已统一改为按实际帧数上限结束。

## 1. 背景与素材状态

### 1.1 新旧视频判定

本次先核对了新旧 MKV 的流哈希、帧数与逐帧时间戳。

| 项目 | 当前修正版 | `旧版/` |
|---|---|---|
| 封装工具 | mkvmerge v103 | FFmpeg / Lavf63.1.101 |
| 首帧 PTS | 0.000s | 0.003s |
| 静止段 | 按 MGV 槽位保留 | 被压缩为固定 24fps |
| 音频/视频流数据 | 与旧版逐字节一致 | 与新版逐字节一致 |
| 时间轴 | 正确 | 错误 |

三支基底帧数：

- 本体：3173 帧，135.628s
- FD：3089 帧，132.000s（容器含音频后为 132.006s）
- RE：2427 帧，103.012s

因此，当前三支视频只需迁移字幕画面锚点，不需要重新处理视频内容，也不能回退到 `旧版/`。

### 1.2 本次要解决的问题

字幕脚本最初是针对旧版时间轴制作的。直接在当前基底上运行会出现两类问题：

1. 歌词与音频本身可以对齐，但画面特效点会错位；
2. 原渲染脚本会改变输出帧数，导致成片不再兼容原 MGV 索引。

---

## 2. 根因分析

### 2.1 根因一：旧版画面时间轴被压缩

旧版由 FFmpeg 直接重封装，静止段被按“帧序 × 1/24s”重新计时，导致：

- 开头/中间静止画面停留时间丢失；
- 最后一帧之前的长静止段被压缩；
- Aegisub 中视频与音频对不上；
- 按旧版画面标的特效点，在当前正确基底上会提前或错位。

因此不能直接把旧版视频时间戳套回当前视频。

### 2.2 根因二：`overlay` 默认会延长视频

原始脚本使用：

```text
[1:v][0:v]overlay=0:0
```

当字幕裸流比基底长时，overlay 会在基底结束后继续重复最后一帧，直到字幕流结束。

短段测试中，基底只有 27 帧，却输出了 52 帧，说明尾帧会被冻结延长。这会让成片帧数与 MGV 索引不兼容。

修复后的约束：

```text
[1:v][0:v]overlay=0:0:shortest=1
```

基底结束即停止，不补冻结帧。

### 2.3 根因三：`-fps_mode vfr` 会丢帧

第一次正式渲染本体时：

- 基底：3173 帧
- 输出：3148 帧
- 丢失：25 帧
- 输出画面结束在约 132 秒，最后一张 135.292 秒画面消失

`vfr` 会为了维持可变帧率而丢弃它认为重复的帧，在末尾长静止段附近表现尤其危险。

改为：

```text
-fps_mode passthrough
```

`passthrough` 不参与自动补帧/丢帧，按输入时间戳原样传递。

### 2.4 根因四：overlay 在双流同时结束时吃掉最后一个主帧

改成 `passthrough` 后，本体仍只有 3172 帧，恰好少最后一帧。

原因是字幕裸流与基底在相同时间结束，framesync 没有“下一帧”可参考，最后一个主帧没有输出。

验证结果：

| 字幕流末尾 | 输出帧数 |
|---|---:|
| 与基底同时结束 | 3172 |
| 比基底多 1 帧 | 3173 |

因此 `gen.py` 需要比基底最后帧多生成 1 帧：

```python
return int(round(last_pts * FPS)) + 2
```

索引从 0 开始，`+2` 表示“最后一帧索引 + 1 个额外帧”。

### 2.5 根因五：FD 被 `config.DUR` 截断

FD 第二次正式渲染仍有 3088 / 3089 帧，缺少的正是最后一帧 131.958s。

原因是：

- `N` 已经计算为 3169 帧；
- 但 `fi1 = min(N, round(C.DUR * FPS))`；
- FD 的 `DUR = 131.962`，四舍五入后 `fi1 = 3167`；
- 实际只生成到 131.917s，覆盖不到基底的 131.958s。

修复：

```python
_T1 = float(os.environ.get("PREVIEW_END", N / C.FPS + 1.0))
```

没有显式预览区间时，默认按实际帧数上限生成，不再被 `DUR` 截断。`PREVIEW_END` 显式设置时仍按预览区间工作。

## 3. 脚本修改

### 3.1 `render.py`

三套 `render.py` 统一修改：

```text
[1:v][0:v]overlay=0:0:shortest=1
-fps_mode passthrough
-c:a copy
```

并增加：

1. 禁止输出路径覆盖基底视频；
2. 渲染完成后用 `ffprobe -count_frames` 校验输出与基底帧数；
3. 帧数不一致时直接报错，并提示“请勿回写游戏”。

帧数校验是最终防线，不会再静默产出坏片。

涉及文件：

- `本体/字幕制作脚本包/render.py`
- `FD/字幕制作脚本包/render.py`
- `RE/ハピメアRE_OP_字幕制作脚本包-重构/render.py`

### 3.2 `gen.py`

三套 `gen.py` 统一修改：

1. 通过 `ffprobe` 读取基底最后一帧 PTS；
2. 字幕裸流帧数 = 最后一帧索引 + 1 个额外帧；
3. 默认结束位置改为 `N / FPS + 1.0`，不再使用 `DUR`；
4. 基底路径按脚本自身目录解析，支持直接从任意工作目录调用。

涉及文件：

- `本体/字幕制作脚本包/gen.py`
- `FD/字幕制作脚本包/gen.py`
- `RE/ハピメアRE_OP_字幕制作脚本包-重构/gen.py`

### 3.3 字幕画面锚点迁移

迁移原则不是“整体平移”，而是逐帧查找：

```text
旧版时间 t
→ 找到旧版当前显示帧的索引 i
→ 读取新版同一索引 i 的 PTS
→ 用新时间替换画面特效锚点
```

这样即使静止段分布不同，特效也仍然绑定同一画面内容。

#### 本体

本体前中段的新旧时间基本一致，主要差异在末尾长静止段。除最终帧覆盖外，不需要整体迁移歌词或主要画面锚点。

#### FD

FD 开头存在约 0.917 秒的静止画面，且中段还有多处静止段，因此多数画面锚点整体后移约 0.83～0.87 秒。

已迁移的主要范围：

- 纯白标题卡：16.32 / 16.82 → 17.167 / 17.667
- 纯白走廊题记：24.65～30.24 → 25.500～31.083
- 昼夜极性翻转：61.83 → 62.667
- 魔导书切镜：64.15 / 64.40 → 65.000 / 65.250
- 副歌各白场/红底/逆光背景阈值
- 85.75 病娇红底白影切镜 → 86.583

涉及：

- `effects/prologue.py`
- `effects/abpart.py`
- `effects/chorus.py`

#### RE

RE 开头存在约 0.208 秒静止段，多数画面锚点后移约 0.125～0.163 秒。

已迁移的主要范围：

- 角色卡切镜：25.50 → 25.625
- 负片闪白：32.330～32.500 → 32.458～32.625
- 紫焰接管：34.167 → 34.292
- 古典金画框：37.25 / 37.35 → 37.375 / 37.500
- 四次鼓点频闪：51.583 / 52.000 / 52.458 / 52.833 → 51.708 / 52.125 / 52.583 / 52.958
- 副歌玫瑰、蝶海、金钥匙、戒指等画面锚点
- 片尾 7 张定格卡全部按同帧迁移，包括黑闪窗口、金框切换、涂抹状态切换

涉及：

- `gen.py`
- `effects/apart.py`
- `effects/bpart.py`
- `effects/chorus.py`

#### 保持不动的时间

以下内容仍使用音频绝对时间：

- `assparse.py` 解析出的歌词句轴；
- `\k` 卡拉 OK 音节；
- 歌词逐字入场、退场；
- 与唱词同时发生的文字动画。

少数同时绑定歌词和角色表演的参数（例如 RE 的 `t_bite`、`t_reach`）保留歌词时间，避免为了画面而破坏音频对轴。

### 3.4 RE 字体路径

RE 原配置只向上找一级字体目录：

```text
../字体
```

实际字体位于项目根目录，RE 脚本需要向上两级。已改为：

```text
../../字体/DFKinBun-W5.ttc
../../字体/DFJinWenW3-GB.ttc
```

否则 RE 会直接报 `FileNotFoundError`，无法启动渲染。

## 6. 后续回写游戏前的约束

当前三个 MKV 是**播放用字幕成片**，不是可直接替换的 `.mgv`。

回写游戏前仍需：

1. 将成片转换为 Theora + Vorbis；
2. 保持帧数、帧序与 MGV 槽位表兼容；
3. 用 `MGV_Editor -mode replace` 替换；
4. 确认新视频帧数没有变化，否则需要同步改写 MGV 索引；
5. 不要使用 FFmpeg 默认重封装，也不要使用 `vfr` 自动丢帧。

本项目三支的基准帧数：

```text
本体：3173 帧 / 24fps / 135.625s 槽位
FD  ：3089 帧 / 24fps / 132.000s 槽位
RE  ：2427 帧 / 24fps / 103.000s 槽位
```

如果后续重新渲染、重新烧字幕或改变分辨率，必须重新执行帧数与时间轴验证。
